# Known issues (V2 working copy)
## Inherited from V1 (still open)
- `run.ps1` and all live downloads untested (see IMPLEMENTATION_STATUS.md).
- Ward file vintage unverified; contains 200 numbered wards + 1 unnumbered 5.7 km2 polygon (flagged, kept). GCC redrew 119 wards and renumbered in Dec 2018 (DTNext, 23 Dec 2018) - confirm which version the file represents.
- WorldCover has no whole-tile fallback if GDAL remote reads are blocked (tile is large). Planned: Earth Engine export or manual drop-in instructions.
- RF script pools all label rasters (union) - incompatible with event-wise validation; to be replaced in the ML module.
- Streamlit `use_container_width` is deprecated in newer Streamlit versions (works, warns).
- Ward file is acquired in A1 (fallback) and A2 (cached on 2nd use; minor duplicated parsing).
- CHIRPS 0.05 deg resampled to 30 m is for display/join only; no spatial information at neighbourhood scale.
## New in V2
- Sentinel-1 scenes in ASF may be missing from Earth Engine's collection (ingestion gaps); S1B checks this and stops with a clear message.
- Earth Engine `getDownloadURL` has a size limit (about 50 MB); Chennai at 30 m is well below it.
- Event dates/peaks in `config/s1_events.json` are approximations from public reports; verify.
- Public flood products found are mostly JPEG/PDF maps; georeferenced rasters/vectors are not guaranteed (the MBRSC 2021 product lists a vector ZIP). Digitising a PDF map into a reference raster is manual work and adds its own error.

## V2.1 open items
- **Why ASF left `rel_orbit` blank is not established.** ASF was unreachable from the build sandbox and the V2.0 code did not keep the raw response. ASF's documentation excerpt I could read defines `relativeOrbit` ("path or track") and `absoluteOrbit` keywords but not the JSON field names; an ASF forum thread shows ASF's relative-orbit values have had errors for Sentinel-1C. V2.1 saves the raw response and `s1_asf_field_diagnostics.json` so the next run shows exactly which fields were present and empty.
- **Derived relative orbit 92 vs the 164 you computed.** By ESA's published formula the five Nov 2015 scenes are relative orbit 92 (164 is absolute orbit mod 175 without the S1A offset of 73). Unconfirmed against Earth Engine until `s1_gee_check.py` runs. Pairing results do not depend on which number is right as long as all scenes are S1A, but the Earth Engine filter in the flood-extent step does, so it must use Earth Engine's own value.
- Earth Engine presence of the five Nov 2015 scenes: NOT QUERIED yet.
- December 2015 scene list was not reported to me; real-data Dec 2015 test is skipped until `tests/fixtures/s1_scenes_2015_dec.csv` (copy of your `s1_scenes_2015_dec.csv`) is added.
- A scene whose catalogue value and derived value disagree is flagged (`orbit_conflict`); the catalogue value is used.

## V2.2 open items (S1B)
- **Earth Engine graph (`build_layers`), live re-check, tile download and Drive export are UNTESTED** (no Earth Engine in the build sandbox). First real run is on your machine; expect possible API-name or size-limit fixes. Fallback: `--mode drive` + `--from-tif`.

## HYD (terrain hydrology) open items
- Real-DEM results unknown until run: the negative-cell cluster may be a source artefact, datum effect or genuine low ground; the analysis only reports evidence and never labels it.
- `--max-fill-depth-m 1.0` is an assumption (see `hydrology_depression_sensitivity.csv`); deep depressions are kept as sinks and cut flow connectivity.
- Study-area edge = outlet (no inflow from outside); 30 m surface DEM ignores culverts/drains; D8 only; TWI is relative and skipped when >30 % of cells need the slope clamp.
- GeoPackage needs geopandas with pyogrio/fiona; if missing, the run is PARTIALLY COMPLETED and says so.

## IMD demo (V2.3-dev)
- Acquisition NOT RUN: build sandbox proxy returns 403 for imdpune.gov.in. No real IMD data obtained or processed; no real rainfall outputs exist.
- The `rainfall.php` POST endpoint is from the third-party `imdlib` client, not documented by IMD. No NetCDF endpoint known: use a manual browser download + `--register`.
- NetCDF variable names, time encoding, missing-value attributes, grid registration (centre assumed), day-label convention and licence are UNVERIFIED; the prepare script inspects and blocks on mismatch.
- Coastal AOI cells may be undefined -> workflow may withhold event totals (INCOMPLETE_COVERAGE <95%); `--min-coverage` is the knob.
- Antecedent rainfall is a completed-day estimate (ends 08:30 IST on D-1), not an exact 24 h pre-pass total. Not validated.
